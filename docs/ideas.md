# Ideas / 想法记录

## 1. 新人入职引导场景

**提出时间**: 2026-09-16  
**状态**: 暂不实现，仅记录

### 核心想法

新人（实习生/新员工）入职时面临的问题：
- 不了解公司整体情况（组织架构、文化、制度）
- 不了解要接手的项目（技术栈、业务背景、代码结构）
- 不知道处理事务该对接谁、走什么流程

### 项目现状分析

admin-ai-agent 定位是**全员行政助手**，目标用户是企业内部全体员工。

现有 11 个业务场景：
- 制度问答、会议室/车辆预定、综合查询、物资领用、请假、证明开具、报销、差旅、固定资产、用印、**入离职办理**

其中 `11-入离职办理.md` 已覆盖**入职手续办理**（签合同、领设备、开账号），但不覆盖"新人融入引导"。

### 现有覆盖 vs 未覆盖

| 维度 | 现有覆盖 | 未覆盖 |
|------|----------|--------|
| 入职手续 | ✅ 签合同、领设备、开账号 | - |
| 公司了解 | - | 组织架构、文化、制度全景 |
| 项目了解 | - | 技术栈、业务背景、代码结构 |
| 流程了解 | - | 对接人、审批流、工具使用 |

### 是否单独做场景的分析

**建议单独做**，理由：
- 服务对象不同：现有场景服务全员，这个只服务新人
- 交互模式不同：现有是"办事"，这个是"学习引导"
- 知识库不同：现有是制度文档，这个需要项目文档 + 组织架构 + 对接人信息

**待考虑**：
- 新人入职痛点是否足够大
- 知识库维护成本（项目文档、组织架构、对接人信息谁来维护）
- 是否值得单独设计引导流程（vs 直接复用现有问答能力）

### 可能的实现方式

1. **公司知识问答** - RAG 检索公司制度文档
2. **项目介绍** - 对接项目文档库，回答架构、技术选型等问题
3. **流程导航** - 告知各类事务的对接人和审批流程
4. **工具使用指导** - 引导使用 HR、审批、日历等内部工具
