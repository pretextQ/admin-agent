# 部署与运维

更新：2026-10-06。当前尚未完成生产部署；本文列出已有运维入口与上线前置。旧 Docker/nginx/监控示例保留在 [部署设计参考](../archive/guides/部署与运维设计参考.md)，不能直接假定可运行。

## 1. 本地环境

本地启动与初始化以 [开发入门](开发入门.md) 为准。旧 `D:/NF/*` 服务路径不是当前机器配置。

| 组件 | 开发用途 | 默认端口 |
|---|---|---|
| 前端 | 员工端 H5/浏览器 | 3000 |
| API | 对话、任务、管理接口 | 8000 |
| OA / 财务 / 物资开发桩 | 模拟下游 | 8001 / 8002 / 8003 |
| PostgreSQL | 主数据 | 5432 |
| Redis | 会话、OAuth state | 6379 |
| Chroma（可选独立服务） | 向量库，服务失败回退本地目录 | 8005 |

## 2. 配置与密钥

配置字段以 `app/admin_ai/config.py` 和 `.env.example` 为准，真实值只放本地或部署环境。生产使用 `ENVIRONMENT=production`；现有启动校验要求非默认且至少 32 字符的 SECRET_KEY、模型 Key、飞书配置、显式 CORS、DEBUG=false、脱敏开启。

启动校验仅检查部分配置，不证明 OAuth 故障处理、审计脱敏、依赖可用性和授权已经符合上线要求；这些修复见 [开发计划](../planning/开发计划.md)。

## 3. 容器部署（待实现）

仓库没有 Dockerfile、Compose、nginx.conf 或 Celery 任务入口，不能直接运行 `docker compose up` 启动项目。计划落地时应同时验证：

- 依赖版本、非 root 镜像、启动命令和迁移流程。
- PostgreSQL、Redis、向量与文件存储持久化。
- 前端路由与 API 反代、TLS、访问范围、密钥注入。
- 下游网络、超时、健康检查和部署后的冒烟。
- WebSocket 端点只有在补齐鉴权与业务流程后才开放；首期可继续 HTTP。

## 4. 数据库迁移

```powershell

.\.venv\Scripts\alembic.exe history
.\.venv\Scripts\alembic.exe upgrade head
```

已有 001 基础表、002 组织与审批、003 条件规则迁移。升级前备份；回滚要先在演练环境检查是否破坏当前数据，不能套用旧环境“已验证”的结论。

## 5. 发布与回滚

目前没有发布流水线。部署文件落地后记录应用版本、依赖、数据库版本与配置差异，验证迁移兼容性和回滚步骤，再做小范围试点。不要把试点环境和开发桩验收混用。

## 6. 备份与恢复

现有脚本：`scripts/db_backup.sh`。在 Git Bash 中先检查脚本的 PG_BIN、连接与备份目录配置，再按脚本帮助使用；它沿用旧机器默认路径。

备份/恢复必须在测试数据库演练并确认表数据、任务、审批与中文内容完整。PostgreSQL 备份不自动包含 `data/chroma`、嵌入模型或未来对象存储附件；向量索引需能从知识文档重建。

保留期、审计存储与恢复目标见 [安全策略](../../SECURITY.md)，其中自动清理、WORM、哈希链等仍是目标设计。备份、授权与删除流程实现后应附演练证据。

## 7. 监控与性能

`/api/health` 是静态存活检查；`/admin/metrics` 部分指标为占位值；未接 Prometheus/Grafana，未完成压测。真实模型调用数、Token、耗时、错误、转人工、下游成功率与告警需在上线前实现。

性能以 [需求说明](../product/需求说明.md) §6.1 为目标：纯检索/规则类首响应 ≤1.5s、需 LLM 生成的首响应 ≤5s、含下游调用的复杂任务完成时间 ≤10s，并发 ≥100。容量和预算按真实部署、调用量与压测结果计算，历史费用估算不作为当前采购依据。

## 8. 组织与业务运维

- 使用 `scripts/sync_org.py` 对接 HR HTTP 或 CSV；同步失败沿用旧快照。
- 补齐真实部门主管、HR/法务角色与业务审批规则；不使用 seed_org_demo 代替真实组织。
- 规则由 `scripts/manage_approval_rules.py` 或管理 API 维护，变更审计与在途单据策略还需验证。
- 定时同步、人工指派、知识运营负责人、供应商数据使用承诺需要明确并留档。
