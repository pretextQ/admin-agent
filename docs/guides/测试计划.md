## 一、测试策略

### 1.1 测试层次

```
┌─────────────────────────────────────┐
│           E2E 端到端测试            │  ← 5%
├─────────────────────────────────────┤
```

### 1.2 测试类型与覆盖率口径

覆盖率口径以本节为准（与 [开发规范.md](开发规范.md) 一致，CI 使用 `--cov-fail-under=80`）：

| 测试类型 | 目的 | 工具 | 覆盖率目标 |
|----------|------|------|-----------|
| 单元测试 | 验证函数/类逻辑 | pytest | Core ≥ 90% |
| 集成测试 | 验证模块间协作 | pytest + httpx | Service ≥ 85% |
| API 测试 | 验证接口行为 | pytest + httpx | API ≥ 80% |
| 整体 | 全量统计 | pytest-cov | ≥ 80% |
| 性能测试 | 验证响应时间/并发 | locust | 关键接口 |
| 安全测试 | 验证权限/注入防护 | 手动 + 工具 | 关键场景 |

> 说明：不再对 API 层单独要求 100% 行覆盖。API 契约的完整性由「四、集成测试」的信封断言与「五、LLM 非确定性与评测」的黄金测试集共同保证。

### 1.4 pytest 标记（markers）

`pyproject.toml` 已启用 `--strict-markers`，未登记的标记会让用例直接报错。自定义标记在 `tests/conftest.py` 的 `pytest_configure` 中统一注册：

| 标记 | 用途 | 是否默认执行 |
|------|------|--------------|
| `slow` | 单条耗时 > 2s 的用例 | 否，本地可 `-m "not slow"` 跳过 |
| `integration` | 需要 PostgreSQL / Redis 等真实依赖 | 是（CI 全量） |
| `e2e` | 跨模块端到端用例 | 是（CI 夜间全量） |
| `llm` | 调用真实 LLM，有费用且非确定 | 否，默认 `-m "not llm"` |
| `asyncio` | pytest-asyncio 异步用例 | 是，`asyncio_mode = "auto"` 自动应用 |

```python
# tests/conftest.py
from __future__ import annotations


def pytest_configure(config) -> None:
    """注册自定义标记，配合 pyproject 的 --strict-markers 使用。"""
    markers = {
        "slow": "耗时较长的用例，本地可用 -m 'not slow' 跳过",
        "integration": "需要 PostgreSQL / Redis 等真实依赖的集成测试",
        "e2e": "跨模块端到端用例",
        "llm": "调用真实 LLM 的用例，默认跳过以避免费用与非确定性",
        # pytest-asyncio 自带 asyncio 标记，此处显式登记以保持 --strict-markers 下的文档一致性
        "asyncio": "pytest-asyncio 异步用例（asyncio_mode=auto 时自动应用）",
    }
    for name, description in markers.items():
        config.addinivalue_line("markers", f"{name}: {description}")
```

> `asyncio` 标记由 pytest-asyncio 自动注册，这里再次登记不产生副作用，仅保证文档与 `--strict-markers` 行为一致。也可改为在 `pyproject.toml` 的 `[tool.pytest.ini_options] markers` 中声明，二选一即可。

## 二、conftest.py 设计

现有测试示例引用了大量 fixture，本节补齐其职责与最小可用实现。所有外部依赖（PostgreSQL、Redis、Chroma、LLM）在测试中都被替换或指向测试实例，保证用例离线、可重复。

### 2.1 Fixture 清单

| Fixture | Scope | 职责 |
|---------|-------|------|
| `settings` | session | 测试配置（测试库、关闭真实 RAG/LLM） |
| `_prepare_database` | session (autouse) | 建表/清表兜底；CI 中由 `alembic upgrade head` 完成 |
| `db_session` | function | 每个用例独立事务，结束回滚，隔离用例 |
| `client` | function | 基于 `ASGITransport` 的进程内 HTTP 客户端，覆盖 `get_db_session` 依赖 |
| `auth_headers` | function | 普通员工 JWT 请求头 |
| `admin_headers` | function | 管理员 JWT 请求头 |
| `user_a_headers` / `user_b_headers` | function | 两个不同用户，用于越权用例 |
| `user_b_task` | function | 属于 user_b 的任务记录，用于越权访问测试 |
| `sample_task` | function | 当前用户的待确认任务，用于 `/chat/confirm` 用例 |
| `mock_llm` | function | LLM 桩，按输入返回预置 JSON |
| `chroma_client` | function | 临时 Chroma 客户端 + 独立 collection |
| `mock_embedder` | function | 固定维度向量，避免加载真实 embedding 模型 |
| `mock_user_service` | function | 用户/假期余额桩 |
| `mock_config_service` | function | 报销标准/预算等配置桩 |
| `mock_oa_service` | function | 用 `respx` 拦截外部网关 HTTP 调用 |
| `redis_client` | function | `fakeredis` 实例，或指向测试 Redis 的独立 db |

### 2.2 关键实现片段

```python
# -*- coding: utf-8 -*-
# Copyright 2026  Admin AI Team, All rights reserved.
"""全局测试 fixtures。

提供测试数据库会话、HTTP 客户端、认证头与 LLM 桩对象，供 tests/admin_ai 下的
用例直接使用。数据库、Redis、Chroma、LLM 等外部依赖在测试中均被替换，
保证用例可离线、可重复执行。
"""

from __future__ import annotations

from collections.abc import AsyncGenerator, Generator
from typing import Any
from unittest.mock import AsyncMock

import pytest
from httpx import ASGITransport, AsyncClient
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

from app.admin_ai.config import get_config
from app.admin_ai.db.database import get_db_session
from app.admin_ai.main import create_app

TEST_DATABASE_URL = "postgresql+asyncpg://postgres:postgres@localhost:5432/admin_ai_test"

test_engine = create_async_engine(TEST_DATABASE_URL, pool_pre_ping=True)
TestSessionFactory = async_sessionmaker(test_engine, expire_on_commit=False)


@pytest.fixture(scope="session")
def settings() -> Any:
    """测试环境配置。"""
    config = get_config()
    config.DEBUG = True
    return config


@pytest.fixture(scope="session", autouse=True)
def _prepare_database() -> Generator[None, None, None]:
    """数据库准备钩子。

    本地可直接建表；CI 中先执行 alembic upgrade head，本 fixture 仅做兜底。
    """
    yield


@pytest.fixture
async def db_session() -> AsyncGenerator[AsyncSession, None]:
    """每个用例一个事务，结束回滚，保证用例之间互不污染。"""
    async with test_engine.connect() as connection:
        transaction = await connection.begin()
        session = AsyncSession(bind=connection, expire_on_commit=False)
        try:
            yield session
        finally:
            await session.close()
            await transaction.rollback()


@pytest.fixture
async def client(db_session: AsyncSession) -> AsyncGenerator[AsyncClient, None]:
    """进程内 HTTP 客户端，并把测试会话注入到 get_db_session 依赖。"""
    fastapi_app = create_app()
    fastapi_app.dependency_overrides[get_db_session] = lambda: db_session
    transport = ASGITransport(app=fastapi_app)
    async with AsyncClient(transport=transport, base_url="http://testserver") as http_client:
        yield http_client
    fastapi_app.dependency_overrides.clear()


@pytest.fixture
async def auth_headers(db_session: AsyncSession) -> dict[str, str]:
    """普通员工身份，返回可直接用于请求的 Bearer 请求头。"""
    from app.admin_ai.core.auth.tokens import create_access_token

    token = create_access_token(user_id="user_001", role="employee")
    return {"Authorization": f"Bearer {token}"}


@pytest.fixture
def mock_llm() -> AsyncMock:
    """LLM 桩：按输入返回预置 JSON，避免真实调用的费用与非确定性。"""
    mock = AsyncMock()

    def _completion(content: str) -> Any:
        message = type("Message", (), {"content": content})()
        choice = type("Choice", (), {"message": message})()
        return type("Completion", (), {"choices": [choice]})()

    async def _create(*args: Any, **kwargs: Any) -> Any:
        prompt = kwargs.get("messages", [{}])[-1].get("content", "")
        if "请假" in prompt:
            return _completion(
                '{"intent": "leave_request", "business_type": "leave", "confidence": 0.95}'
            )
        return _completion('{"intent": "policy_query", "confidence": 0.9}')

    mock.chat.completions.create.side_effect = _create
    return mock
```

补充说明：

- `asyncio_mode = "auto"` 已开启，异步用例无需再加 `@pytest.mark.asyncio`。
- 若需要触发 FastAPI `lifespan`（初始化 Redis、工具注册），在 `client` 中包一层 `asgi_lifespan.LifespanManager`，并把 `asgi-lifespan` 加入 pyproject 的 dev 依赖组。
- `chroma_client` 建议使用 `chromadb.EphemeralClient()` 并为每个用例生成独立 collection；`mock_embedder` 返回固定维度（如 384）归一化向量。
- `mock_oa_service` 优先使用 `respx` 按 URL 匹配，避免真实外呼。

### 4.1 测试范围

| 场景 | 测试点 |

| 对话流程 | 消息发送 → 意图识别 → 响应返回 |

### 4.2 响应信封约定

所有接口统一返回 `{code, message, data}`（成功 `code=0`），错误返回 `{code, message, details}`，HTTP 状态码保持语义化（400/401/403/404/429/5xx）。因此断言需同时校验 HTTP 状态码与 `code` 字段。

### 4.3 测试示例

```python
# tests/admin_ai/test_api/test_chat.py
from __future__ import annotations

from httpx import AsyncClient


class TestChatAPI:
    """对话 API 测试。"""

    async def test_send_message_create_conversation(
        self, client: AsyncClient, auth_headers: dict[str, str]
    ) -> None:
        """测试发送消息创建新会话。"""
        response = await client.post(
            "/api/v1/chat/send",
            json={"message": "你好"},
            headers=auth_headers,
        )

        assert response.status_code == 200
        data = response.json()
        assert data["code"] == 0
        assert "conversation_id" in data["data"]
        assert "content" in data["data"]

    async def test_send_message_continue_conversation(
        self, client: AsyncClient, auth_headers: dict[str, str]
    ) -> None:
        """测试继续已有会话。"""
        resp1 = await client.post(
            "/api/v1/chat/send",
            json={"message": "我想请假"},
            headers=auth_headers,
        )
        assert resp1.json()["code"] == 0
        conversation_id = resp1.json()["data"]["conversation_id"]

        resp2 = await client.post(
            "/api/v1/chat/send",
            json={"message": "年假", "conversation_id": conversation_id},
            headers=auth_headers,
        )

        assert resp2.status_code == 200
        assert resp2.json()["code"] == 0
        assert resp2.json()["data"]["conversation_id"] == conversation_id

    async def test_get_conversation_history(
        self, client: AsyncClient, auth_headers: dict[str, str]
    ) -> None:
        """测试获取会话历史。"""
        resp = await client.post(
            "/api/v1/chat/send",
            json={"message": "你好"},
            headers=auth_headers,
        )
        conversation_id = resp.json()["data"]["conversation_id"]

        response = await client.get(
            f"/api/v1/chat/history/{conversation_id}",
            headers=auth_headers,
        )

        assert response.status_code == 200
        data = response.json()
        assert data["code"] == 0
        assert len(data["data"]["messages"]) >= 2  # 用户消息 + 助手回复

    async def test_confirm_action(
        self, client: AsyncClient, auth_headers: dict[str, str], sample_task: dict
    ) -> None:
        """测试确认高风险操作。"""
        response = await client.post(
            f"/api/v1/chat/confirm/{sample_task['id']}",
            json={"confirmed": True, "comment": "确认无误"},
            headers=auth_headers,
```

## 五、LLM 非确定性与评测

LLM 输出具有非确定性，不能只靠普通断言覆盖，需要单独的评测层。

### 5.1 非确定性来源与控制

- 单测与集成测试一律使用 `mock_llm`，不触达真实模型。
- 需要真实模型的用例统一加 `@pytest.mark.llm`，默认通过 `-m "not llm"` 跳过，仅在评测流水线或手动触发时执行。
- 调用侧固定 `temperature=0`、`response_format={"type": "json_object"}`，并在可用时传入 `seed`；对结果只断言结构化字段与阈值，不断言逐字文本。
- 引入 prompt/响应快照（录制回放）机制，保证回归可重复；模型或 prompt 变更时显式更新快照并 review。

### 5.2 意图识别黄金测试集

- 数据：`tests/data/intent_golden.jsonl`，建议 ≥ 200 条，覆盖全部 14 类意图标签与边界输入（多意图、口语、错别字、超纲问题）。
- 字段：`text`、`history`（可选）、`expected_intent`、`expected_business_type`、`tags`。
- 指标：整体准确率、分类别 Precision/Recall/F1、混淆矩阵。
- 门槛：第 2 周 ≥ 85%；M4/上线 ≥ 92%（与需求文档 7.1 一致）。
- 运行：`pytest -m llm tests/admin_ai/test_core/test_intent_eval.py`。

### 5.3 RAG 忠实度与命中率评测

- 数据：`tests/data/rag_golden.jsonl`，每条含问题、标准答案、来源文档/切片 ID。
- 指标：
  - 命中率 Hit@k（k=5）：标准来源是否进入 top-k；阶段目标 ≥ 80%。
  - MRR：首个正确来源的倒数排名均值。
  - 忠实度（Faithfulness）：答案是否可由检索内容支撑，采用人工抽检 + LLM-as-judge 双轨，抽检比例不低于 10%。
  - 空结果行为：无命中时必须返回「未找到」而非编造。
- 运行：`pytest -m llm tests/admin_ai/test_core/test_rag_eval.py`。

### 5.4 Prompt 回归测试

- Prompt 模板纳入版本管理（`prompt_version`），并写入消息元数据与审计日志。
- 修改 Prompt 时必须跑黄金集，新版本指标不得低于旧版本；若下降超过阈值则阻断合并。
- 关键 Prompt 使用快照测试，变更需人工确认 diff。

## 六、性能测试

### 6.1 测试指标

目标值以需求文档 §6.1 为基准（200 人企业规模，2026-09-20 三处口径已统一）：

| 指标 | 目标值 | 测试方法 |
|------|--------|----------|
| 首响应时间（纯检索/规则类） | ≤ 1.5s | 单请求计时 |
| 首响应时间（需 LLM 生成） | ≤ 5s | 单请求计时 |
| 复杂任务处理（含下游系统调用） | ≤ 10s | 端到端计时 |
| 并发用户数 | ≥ 100 | 压力测试 |
| 峰值承载 | 按日均 5~10 倍模型 | 压力测试（峰值场景：早高峰 / 月末） |
| QPS | ≥ 50 | 压力测试 |
| 错误率 | < 1% | 压力测试 |

> 新增建议指标（LLM 是主要延迟与成本来源，建议随 RAG/LLM 落地补齐）：
> LLM 调用 P95 延迟、LLM 超时率、降级触发率（规则回退/模板回退次数）、单会话 Token 成本。

### 6.2 压测环境规格

压测环境需与生产同规格或按比例缩放，避免结论失真：

| 组件 | 规格 | 说明 |
|------|------|------|
| API 服务 | 4C8G × 2 | 与资源规划一致，容器限额 2C4G |
| PostgreSQL | 2C4G | 独立实例，预置接近生产的数据量 |
| Redis | 2G | 独立实例 |
| ChromaDB | 独立实例 | 预置制度知识库切片 |
| 数据量 | ≥ 1 万条会话/任务 | 避免空库跑出虚高指标 |
| 预热 | ≥ 5 分钟 | 排除冷启动影响 |

压测使用独立环境，不与其他测试或演示环境混跑。
