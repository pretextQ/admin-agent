# 测试计划

更新：2026-10-06。本文提供当前可用检查与补测范围；历史测试模板见 [测试设计参考](../archive/guides/测试设计参考.md)。验证结果只维护在 [当前状态](当前状态.md)。

## 1. 默认单元测试

在项目根、已经安装 requirements-dev 的虚拟环境中：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/admin_ai -q
```

`pyproject.toml` 默认排除 integration、e2e、llm 标记。多数外部调用和审计数据库使用 mock，因此通过不能证明真实 PostgreSQL、Redis、下游系统或模型可用。

## 2. 数据库集成测试

先配置测试用数据库并执行迁移，阅读测试中的 fixture 与清理逻辑，避免指向生产数据库。现有集成用例主要覆盖组织/审批与状态查询。

```powershell
.\.venv\Scripts\python.exe -m pytest tests/admin_ai -m integration -q
```

不要把旧环境的 27 个通过记录当成当前环境测试结果。测试隔离、外键插入顺序和事件循环连接池约定见 [开发规范](开发规范.md#31-工程硬约定踩坑沉淀)。

## 3. 开发桩端到端冒烟

需要 PostgreSQL、Redis、开发桩和 API；执行过 seed_admin 与 seed_org_demo，并使用 development 环境。

```powershell
$env:PYTHONPATH = '.'
.\.venv\Scripts\python.exe scripts/e2e_smoke.py
```

脚本包含 11 个编号步骤：员工请假、报销确认、主管审批、历史、状态查询及受理编号回查。下游为 `scripts/dev_stubs.py`，不能作为真实 OA 或财务验收证据。配置真实模型 Key 时可能产生调用费用；初次可用空 Key 走规则回退。

## 4. 前端检查

```powershell
Set-Location frontend
pnpm install --frozen-lockfile
pnpm lint
pnpm build
```

build 包含 TypeScript 检查与 Vite 构建。虽然声明了 Vitest / Testing Library，当前 package.json 没有 test 脚本，也没有已落地的前端用例；先补基础配置和关键业务用例，再把测试加入流程。

## 5. 代码质量与覆盖率

```powershell
.\.venv\Scripts\ruff.exe check app/ tests/
.\.venv\Scripts\ruff.exe format --check app/ tests/
.\.venv\Scripts\mypy.exe app/
.\.venv\Scripts\python.exe -m pytest --cov=app.admin_ai --cov-report=term-missing --cov-fail-under=80
```

整体覆盖率 80%、Core 90%、Service 85%、API 80% 是工程目标，不是已达成结果；分层目标目前也没有独立自动门禁。旧文档中的 lint 数量不再沿用，请记录实际版本与检查输出。

## 6. 优先补测

- 规则与工具：负数/零/非数字、日期、未知 action、参数白名单、下游超时/失败。
- 授权：OAuth state 异常、停用账号、会话越权、审批步序和角色变更。
- 一致性：并发确认、重复提交、审批回调重复/乱序、部分成功后重试、取消与下游效果。
- RAG：中文命中、无命中、超时、删除失败、失效文档不可引用。
- 前端：补槽、确认/取消、审批/驳回、历史恢复、分页、401 和错误提示。
- 上线验证：限流、监控、依赖故障、备份恢复、部署和性能压测。

性能按 [需求说明](../product/需求说明.md) §6.1 的分级响应目标评估：纯检索/规则类首响应 ≤1.5s、需 LLM 生成的首响应 ≤5s、含下游调用的复杂任务完成时间 ≤10s，并发目标 ≥100；这些均为待验证目标。长流程的首响应与完成时间需分开记录。

当前没有 CI、性能脚本或完整安全测试门禁。规划模板中的配置、用例和断言不等于仓库已经实现。
