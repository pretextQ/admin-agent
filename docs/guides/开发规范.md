## 一、环境管理

### 1.1 使用 uv 管理环境

本项目使用 [uv](https://github.com/astral-sh/uv) 作为 Python 环境和包管理工具。

```bash
# 安装 uv
curl -LsSf https://astral.sh/uv/install.sh | sh
# 或
pip install uv

# 创建虚拟环境
uv venv

# 激活环境
source .venv/bin/activate  # Linux/Mac
# 或
.venv\Scripts\activate  # Windows

# 安装依赖
uv pip install -r requirements.txt

# 安装开发依赖
uv pip install -r requirements-dev.txt

# 添加新依赖
uv pip install package_name

# 同步环境（安装所有依赖）
uv pip sync requirements.txt
```

### 1.2 依赖管理

```bash
# requirements.txt      - 生产依赖
# requirements-dev.txt  - 开发依赖（包含 requirements.txt）

# 生成锁定文件
uv pip compile requirements.txt -o requirements.lock
uv pip compile requirements-dev.txt -o requirements-dev.lock
```

### 2.2 代码风格要点

| 要点 | 说明 |
|------|------|
| 文件编码 | 使用 `# -*- coding: utf-8 -*-` |
| 类型注解 | 所有公共 API 必须有类型注解 |
| 文档字符串 | 所有类和公共方法必须有文档字符串 |
| 异步优先 | IO 操作使用 async/await |
| 日志 | 使用 logging 模块，不使用 print |
| 导入顺序 | 标准库 → 第三方库 → 本地模块 |

## 三、Git 规范

### 3.1 分支策略

```
main          ← 生产分支，只接受 PR
  └── develop ← 开发分支
       ├── feature/xxx  ← 功能分支
       ├── bugfix/xxx   ← Bug 修复
       └── hotfix/xxx   ← 紧急修复
```

### 3.2 Commit 规范

```
<type>(<scope>): <subject>

类型：
- feat:     新功能
- fix:      Bug 修复
- docs:     文档
- style:    代码格式（不影响逻辑）
- refactor: 重构
- test:     测试
- chore:    构建/工具

示例：
feat(chat): 添加多轮对话支持
fix(intent): 修复意图识别置信度计算错误
docs(api): 更新 API 接口文档
```

### 3.3 PR 规范

```markdown

## 变更类型
- [ ] 新功能

- [ ] 单元测试通过
- [ ] 集成测试通过
```

## 四、API 设计规范

### 4.1 RESTful 规范

```
# 资源命名：复数名词
GET    /api/v1/users           # 获取列表

# 业务动作：动词
POST   /api/v1/chat/send       # 发送消息
POST   /api/v1/tasks/{id}/approve  # 审批任务
```

### 4.2 响应格式

```json
// 成功响应
{
    "code": 0,
    "message": "success",
    "data": {
        "id": "xxx",
        "name": "xxx"
    }
}

// 列表响应
{
    "code": 0,
    "message": "success",
    "data": {
        "items": [...],
```

## 五、数据库规范

### 5.1 表设计规范

```sql
-- 表名：小写下划线，复数
CREATE TABLE users (
    id          VARCHAR(36) PRIMARY KEY,  -- UUID 主键
    employee_id VARCHAR(50) UNIQUE NOT NULL,  -- 业务唯一键
    name        VARCHAR(100) NOT NULL,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_deleted  BOOLEAN DEFAULT FALSE  -- 软删除标记
);

-- 索引命名：idx_表名_字段名
CREATE INDEX idx_users_employee_id ON users(employee_id);
CREATE INDEX idx_users_department ON users(department);
```

### 5.2 迁移规范

```bash
# 创建迁移
alembic revision --autogenerate -m "add users table"

# 执行迁移
alembic upgrade head

# 回滚迁移
alembic downgrade -1
```

## 七、日志规范

### 7.1 日志级别

```python
import logging

logger = logging.getLogger(__name__)

# DEBUG：调试信息
logger.debug("槽位抽取详情", extra={"slots": slots})

# INFO：关键流程
logger.info("消息处理完成", extra={"user_id": user_id, "intent": intent})

# WARNING：异常但可恢复
logger.warning("LLM 调用超时，重试中", extra={"attempt": attempt})

# ERROR：错误需要关注
logger.error("工具调用失败", extra={"tool": tool_name, "error": str(e)})

# CRITICAL：严重错误
logger.critical("数据库连接失败", extra={"error": str(e)})
```

## 八、安全规范

### 8.1 敏感信息处理

```python
# ❌ 错误：明文存储密码
password = "123456"

# ✅ 正确：使用哈希
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"])
hashed_password = pwd_context.hash(password)

# ❌ 错误：日志输出敏感信息
logger.info("用户信息", extra={"user": user})

# ✅ 正确：脱敏处理
logger.info("用户信息", extra={"user_id": user.id, "name": user.name[:1] + "***"})
```

## 九、文档规范

### 9.1 代码注释

```python
# 单行注释：说明"为什么"而不是"是什么"
# 使用 Redis 缓存会话，避免频繁数据库查询
session = await redis.get(f"session:{session_id}")

# 复杂逻辑需要块注释
# 这里使用指数退避重试策略：
# 1. 首次失败后等待 1 秒
# 2. 第二次失败后等待 2 秒
# 3. 最多重试 3 次
for attempt in range(max_retries):
    try:
        return await call_api()
    except Exception:
        await asyncio.sleep(2 ** attempt)
```
