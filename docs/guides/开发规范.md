### 1.2 目录结构规范

```
app/
├── api/          # 路由层：只做参数校验和响应封装
├── core/         # 核心业务：业务逻辑实现
├── models/       # 数据模型：SQLAlchemy ORM
├── schemas/      # 请求/响应模型：Pydantic
├── services/     # 服务层：协调多个 core 模块
├── db/           # 数据库：连接、迁移
├── middleware/   # 中间件
└── utils/        # 工具函数：无业务逻辑
```

### 1.3 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | 小写下划线 | `user_service.py` |
| 类名 | 大驼峰 | `UserService` |
| 函数名 | 小写下划线 | `get_user_by_id()` |
| 常量 | 大写下划线 | `MAX_RETRY_COUNT` |
| 私有属性 | 下划线前缀 | `self._internal_cache` |
| 数据库表名 | 小写下划线 | `users`, `audit_logs` |

## 二、Git 规范

### 2.1 分支策略

```
main          ← 生产分支，只接受 PR
  └── develop ← 开发分支
       ├── feature/xxx  ← 功能分支
       ├── bugfix/xxx   ← Bug 修复
       └── hotfix/xxx   ← 紧急修复
```

### 2.2 Commit 规范

```
<type>(<scope>): <subject>

类型：
- feat:     新功能
- fix:      Bug 修复
- docs:     文档
- style:    代码格式（不影响逻辑）
- refactor: 重构
- test:     测试
- chore:    构建/工具

示例：
feat(chat): 添加多轮对话支持
fix(intent): 修复意图识别置信度计算错误
docs(api): 更新 API 接口文档
```

### 2.3 PR 规范

```markdown
## 变更说明
简要描述本次变更

## 变更类型
- [ ] 新功能
- [ ] Bug 修复
- [ ] 重构
- [ ] 文档更新

## 测试情况
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 手动测试通过

## 关联 Issue
Closes #123
```

## 三、API 设计规范

### 3.1 RESTful 规范

```
# 资源命名：复数名词
GET    /api/v1/users           # 获取列表
GET    /api/v1/users/{id}      # 获取详情
POST   /api/v1/users           # 创建
PUT    /api/v1/users/{id}      # 更新
DELETE /api/v1/users/{id}      # 删除

# 业务动作：动词
POST   /api/v1/chat/send       # 发送消息
POST   /api/v1/tasks/{id}/approve  # 审批任务
```

### 3.2 响应格式

```json
// 成功响应
{
    "code": 0,
    "message": "success",
    "data": {
        "id": "xxx",
        "name": "xxx"
    }
}

// 列表响应
{
    "code": 0,
    "message": "success",
    "data": {
        "items": [...],
        "total": 100,
        "page": 1,
        "page_size": 20
    }
}

// 错误响应
{
    "code": 40001,
    "message": "用户不存在",
    "details": {
        "field": "user_id",
        "value": "xxx"
    }
}
```

### 3.3 错误码规范

| 错误码 | 含义 | HTTP 状态码 |
|--------|------|-------------|
| 0 | 成功 | 200 |
| 40001 | 参数错误 | 400 |
| 40002 | 未授权 | 401 |
| 40003 | 无权限 | 403 |
| 40004 | 资源不存在 | 404 |
| 50001 | 内部错误 | 500 |
| 50002 | 外部服务错误 | 502 |
| 50003 | 服务不可用 | 503 |

## 四、数据库规范

### 4.1 表设计规范

```sql
-- 表名：小写下划线，复数
CREATE TABLE users (
    id          VARCHAR(36) PRIMARY KEY,  -- UUID 主键
    employee_id VARCHAR(50) UNIQUE NOT NULL,  -- 业务唯一键
    name        VARCHAR(100) NOT NULL,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_deleted  BOOLEAN DEFAULT FALSE  -- 软删除标记
);

-- 索引命名：idx_表名_字段名
CREATE INDEX idx_users_employee_id ON users(employee_id);
CREATE INDEX idx_users_department ON users(department);
```

### 4.2 迁移规范

```bash
# 创建迁移
alembic revision --autogenerate -m "add users table"

# 执行迁移
alembic upgrade head

# 回滚迁移
alembic downgrade -1
```

## 六、日志规范

### 6.1 日志级别

```python
import structlog

logger = structlog.get_logger()

# DEBUG：调试信息
logger.debug("槽位抽取详情", slots=slots)

# INFO：关键流程
logger.info("消息处理完成", user_id=user_id, intent=intent)

# WARNING：异常但可恢复
logger.warning("LLM 调用超时，重试中", attempt=attempt)

# ERROR：错误需要关注
logger.error("工具调用失败", tool=tool_name, error=str(e))

# CRITICAL：严重错误
logger.critical("数据库连接失败", error=str(e))
```

## 七、安全规范

### 7.1 敏感信息处理

```python
# ❌ 错误：明文存储密码
password = "123456"

# ✅ 正确：使用哈希
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"])
hashed_password = pwd_context.hash(password)

# ❌ 错误：日志输出敏感信息
logger.info("用户信息", user=user)

# ✅ 正确：脱敏处理
logger.info("用户信息", user_id=user.id, name=user.name[:1] + "***")
```


## 八、文档规范

### 8.1 代码注释

```python
# 单行注释：说明"为什么"而不是"是什么"
# 使用 Redis 缓存会话，避免频繁数据库查询
session = await redis.get(f"session:{session_id}")

# 复杂逻辑需要块注释
# 这里使用指数退避重试策略：
# 1. 首次失败后等待 1 秒
# 2. 第二次失败后等待 2 秒
# 3. 最多重试 3 次
for attempt in range(max_retries):
    try:
        return await call_api()
    except Exception:
        await asyncio.sleep(2 ** attempt)
```
