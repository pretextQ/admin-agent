## 一、项目总体计划

### 1.1 项目周期

| 阶段 | 时间 | 主要目标 |
|------|------|----------|
| 阶段一：MVP | 第 1-4 周 | 跑通最小可用版本，验证技术可行性 |
| 阶段二：核心功能 | 第 5-10 周 | 完成高频场景，上线内部测试 |
| 阶段三：完整版 | 第 11-16 周 | 完成全部场景，正式上线 |
| 阶段四：优化迭代 | 第 17 周+ | 持续优化，扩展场景 |

### 1.2 里程碑定义

| 里程碑 | 时间点 | 交付物 | 验收标准 |
|--------|--------|--------|----------|
| M1：技术验证 | 第 2 周末 | 可运行的 FastAPI 骨架 + LLM 调用 demo | 能通过 API 发送消息并获得 LLM 回复 |
| M2：MVP 版本 | 第 4 周末 | 制度问答 + 会议室预定 | 能回答制度问题、能预定会议室 |
| M3：核心场景 | 第 8 周末 | 请假 + 报销 + 物资领用 | 端到端完成请假/报销流程 |
| M4：内部测试 | 第 10 周末 | 完整系统 + 测试报告 | 意图识别准确率 ≥ 90% |
| M5：正式上线 | 第 16 周末 | 生产环境部署 | 通过全部验收指标 |

### 2.2 MVP 功能范围

```
✅ 支持：
- 制度问答（RAG）："年假有几天""报销标准是什么"
- 会议室预定："明天下午2点订个10人会议室"
- 基础多轮对话：信息不全时反问
- 会话状态管理：记住上下文

❌ 不支持（后续迭代）：
- 报销/请假等复杂流程
- 高风险操作人工确认
- 审批流对接
- 转人工机制
```

## 五、阶段四：优化迭代（第 17 周+）

### 5.1 持续优化方向

| 方向 | 内容 | 优先级 |
|------|------|--------|
| 准确率优化 | 意图识别/槽位抽取准确率提升 | P0 |
| 知识库扩充 | 更多制度文档/FAQ 入库 | P0 |
| 场景扩展 | 覆盖更多长尾场景 | P1 |
| 智能决策 | 预算预测、采购补货建议 | P2 |
| 多语言支持 | 英文/方言支持 | P3 |

### 5.2 数据驱动迭代

```
每周分析：
1. 意图识别失败案例 → 优化 Prompt/模型
2. 转人工案例 → 分析原因，扩展自动化范围
3. 用户满意度低案例 → 优化交互体验
4. 高频问题 → 沉淀为 FAQ/快捷指令
```

## 七、风险管理

### 7.1 关键风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| LLM 准确率不达标 | 高 | 中 | 预留 2 周优化时间；准备降级方案 |
| 外部系统对接困难 | 高 | 高 | 提前调研接口；准备 RPA 兜底 |
| 需求变更频繁 | 中 | 中 | 采用敏捷开发；每 2 周评审 |
| 人员变动 | 中 | 低 | 完善文档；代码规范 |

### 7.2 里程碑检查点

| 检查点 | 时间 | 决策 |
|--------|------|------|
| M1 检查 | 第 2 周末 | 技术可行性确认，是否继续 |
| M2 检查 | 第 4 周末 | MVP 效果评估，是否调整计划 |
| M3 检查 | 第 8 周末 | 核心功能验收，是否进入测试 |
| M4 检查 | 第 10 周末 | 测试结果评审，是否准备上线 |
