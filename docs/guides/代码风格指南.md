# 代码风格指南

> 版本：V1.1　|　更新日期：2026-09-15
>
> 参考实现：[atlasclaw](https://gitee.com/qiulongfei4408/atlasclaw)。本指南中的约定均以该仓库的实际代码为准，而不是凭想象规定。

---

## 0. 总原则

| 原则 | 说明 |
|------|------|
| 可读性优先 | 代码是写给人看的，顺便让机器执行 |
| 显式优于隐式 | 不做魔法式约定，依赖关系写在签名和构造函数里 |
| 单一职责 | 一个模块/类/函数只做一件事 |
| 接口稳定 | 公共函数必须有完整类型注解和文档字符串 |
| 就事论事 | 本指南只管代码风格，不决定架构与部署方案 |

每个 `.py` 文件按固定顺序组织：

```python
from __future__ import annotations

MAX_RETRY_COUNT = 3
```

- 版权行主体统一为 `Admin AI Team`；年份取文件创建年份。
- `from __future__ import annotations` 每个新文件都要有。
- 模块文档字符串不可省略。

## 3. 导入规范

- 顺序：标准库 → 第三方 → 本地模块，组间空一行。
- 使用绝对导入：`from app.admin_ai.core.config import get_config`。
- 同包内允许相对导入：`from .models import UserModel`。
- 只用类型时才需要的导入放 `TYPE_CHECKING`：

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from app.admin_ai.core.agent.runner import AgentRunner
```

- 禁止通配符导入（`from x import *`）。
- 启动开销大的依赖在函数内延迟导入（例如重模型客户端）。
- 导入排序由 Ruff（`I` 规则）自动完成，不要手工争论顺序。

## 4. 命名规范

| 类型 | 风格 | 示例 |
|------|------|------|
| 包名 | 小写无下划线 | `admin_ai`, `core`, `db` |
| 模块名 | 小写下划线 | `user_service.py`, `database.py` |
| 类名 | 大驼峰 | `UserService`, `AgentOrchestrator` |
| 异常类 | 大驼峰，`Error` 结尾 | `ToolExecutionError` |
| 函数/方法 | 小写下划线，动宾结构 | `get_user_by_id()`, `validate_input()` |
| 变量 | 小写下划线 | `session_key`, `max_retry_count` |
| 常量 | 大写下划线 | `MAX_RETRY_COUNT`, `DEFAULT_TIMEOUT` |
| 枚举成员 | 大写下划线 | `TaskStatus.APPROVING` |
| 枚举值 | 小写字符串 | `"approving"` |
| 私有成员 | 下划线前缀 | `self._internal_cache` |
| 数据库表名 | 小写下划线、复数 | `users`, `audit_logs` |
| 数据库列名 | 小写下划线 | `created_at` |
| 测试类 | `Test` + 大驼峰 | `TestIntentRecognizer` |
| 测试函数 | `test_<行为>` | `test_recognize_leave_request` |

```python
# Good
def fetch_user_data() -> dict[str, Any]: ...
def validate_input(payload: dict) -> bool: ...

# Bad：名词当函数名
def user_data(): ...
def validation(): ...
```

## 5. 类型注解

- **所有**函数参数与返回值必须有类型注解，包括 `__init__` 和私有方法。
- 可空类型统一写 `Optional[T]`，不写 `T | None`。
- 容器类型使用内置泛型小写形式：`dict[str, Any]`、`list[str]`、`tuple[bool, str]`。
- 动态类型（LLM 响应、外部 API 原始返回）用 `Any`。

```python
from typing import Any, Optional

def get_user_by_id(
    user_id: str,
    include_deleted: bool = False
) -> Optional[UserModel]:
    """根据 ID 获取用户。"""
    ...

async def create_user(
    payload: UserCreateSchema,
    *,
    created_by: Optional[str] = None
) -> UserModel:
    """创建用户。"""
    ...
```

## 6. 数据容器：@dataclass 还是 Pydantic

| 场景 | 选择 |
|------|------|
| 内部数据容器、工具返回、上下文对象、配置项对象 | `@dataclass` |
| 需要校验或序列化的 API 请求/响应、配置模型 | `pydantic.BaseModel` |

```python
from dataclasses import dataclass, field
from typing import Any, Optional


@dataclass
class ToolResult:
    """工具执行的统一返回结构。"""

    content: list[dict] = field(default_factory=list)
    details: dict[str, Any] = field(default_factory=dict)
    is_error: bool = False

    @classmethod
    def text(cls, text: str, details: Optional[dict] = None) -> "ToolResult":
        """构造一个文本结果。"""
        return cls(content=[{"type": "text", "text": text}], details=details or {})

    @classmethod
    def error(cls, message: str, details: Optional[dict] = None) -> "ToolResult":
        """构造一个错误结果。"""
        return cls(
            content=[{"type": "text", "text": message}],
            details=details or {},
            is_error=True,
        )
```

- 可变默认值必须用 `field(default_factory=...)`，禁止 `= []` / `= {}`。

## 7. 枚举

字符串常量统一用 `class X(str, Enum)`：

```python
from enum import Enum


class TaskStatus(str, Enum):
    """任务状态。"""

    PENDING = "pending"
    PROCESSING = "processing"
    APPROVING = "approving"
    COMPLETED = "completed"
    FAILED = "failed"
    CANCELLED = "cancelled"
```

- 禁止用「裸字符串比较」代替枚举：`if status == "approving"` 在跨模块处应改为 `TaskStatus.APPROVING`。

## 8. 文档字符串（Google 风格）

所有模块、公共类、公共方法都要有文档字符串：

```python
async def get_user_by_id(user_id: str) -> Optional[UserModel]:
    """根据用户 ID 获取用户信息。

    从数据库查询指定 ID 的用户，不存在时返回 None。

    Args:
        user_id: 用户唯一标识符。

    Returns:
        Optional[UserModel]: 用户对象，不存在返回 None。

    Raises:
        ValueError: 当 user_id 为空字符串时。
        DatabaseError: 当数据库查询失败时。
    """
    ...
```

- 简单函数可以用一句话文档字符串。
- 注释解释「为什么」，不解释「是什么」：

```python
# Good：说明原因
# 补偿时区偏移对日期计算的影响
adjusted_date = raw_date + timedelta(hours=timezone_offset)

# Bad：复述代码
# 计数加一
count += 1
```

## 9. 类与函数结构

```python
class UserService:
    """用户服务类。

    Attributes:
        db: 异步数据库会话。
    """

    # 1. 类常量
    DEFAULT_PAGE_SIZE = 20

    # 2. 构造函数
    def __init__(self, db: AsyncSession) -> None:
        """初始化用户服务。

        Args:
            db: 异步数据库会话。
        """
        self._db = db

    # 3. 类方法 / 工厂方法
    @classmethod
    def from_dict(cls, data: dict[str, Any]) -> "UserService":
        """从字典构造实例。"""
        ...

    # 4. 公共方法
    async def get_user(self, user_id: str) -> Optional[UserModel]:
        """获取用户。"""
        ...

    # 5. 私有方法
    def _validate_user_data(self, data: dict) -> bool:
        """校验用户数据。"""
        ...

    # 6. 魔术方法
    def __repr__(self) -> str:
        return f"<UserService(db={self._db})>"
```

- 数据类用 `@dataclass`，行为类用普通 `class`。
- 只读属性用 `@property`，不要写 `get_xxx()` 方法。
- 工厂方法统一命名 `from_dict()` / `from_config()` / `from_string()`。
- 进程级单例用模块级函数 + 全局变量：

```python
_config: Optional[Settings] = None


def get_config() -> Settings:
    """获取全局配置单例。"""
    global _config
    if _config is None:
        _config = Settings()
    return _config
```

- 函数保持短小（20~50 行）；复杂函数先拆分再实现。
- 大类用 Mixin 拆分，而不是无限堆方法。

## 10. 异步编程

- 所有 I/O 操作必须异步：数据库、HTTP、文件、子进程。
- 禁止在 `async def` 中调用同步阻塞库（`requests`、同步的 ChromaDB 客户端等）；无法异步时用 `asyncio.to_thread()`。

```python
# Good
async def fetch_data(url: str) -> dict[str, Any]:
    async with httpx.AsyncClient(timeout=30) as client:
        response = await client.get(url)
        response.raise_for_status()
        return response.json()

# Bad：阻塞事件循环
async def fetch_data_bad(url: str) -> dict[str, Any]:
    return requests.get(url).json()
```

- 并发用 `asyncio.gather()`；取消/中止信号用 `asyncio.Event`。
- 共享可变状态的并发写必须加锁（如每个会话一把 `asyncio.Lock`）。
- 资源管理用 `async with` / `@asynccontextmanager`，确保释放。

## 11. 错误处理

### 11.1 异常层级

```python
class AppError(Exception):
    """应用基础异常。"""


class UserNotFoundError(AppError):
    """用户不存在。"""


class ToolExecutionError(AppError):
    """工具执行失败。"""


class ExternalSystemError(AppError):
    """外部系统调用失败。"""
```

### 11.2 规则

- 捕获具体异常，禁止裸 `except:` 和空 `except` 块。
- 重新抛出时保留异常链：`raise ExternalSystemError(...) from exc`。
- 预期内的失败用结果对象（`ToolResult.error(...)` / `success=False`），不要用异常做流程控制。
- API 边界统一由异常处理器转换为响应信封（见第 14 节）。

```python
try:
    user = await user_service.get_by_id(user_id)
except SQLAlchemyError as exc:
    logger.error("数据库查询失败", extra={"user_id": user_id, "error": str(exc)})
    raise DatabaseError(f"查询用户失败: {user_id}") from exc

if user is None:
    raise UserNotFoundError(f"用户不存在: {user_id}")
```

## 12. 日志规范

使用 `structlog`（应用层）与标准 `logging`（库/模块层），**不使用 `print()`**。

```python
import structlog

logger = structlog.get_logger(__name__)

logger.debug("槽位抽取详情", slots=slots)
logger.info("消息处理完成", user_id=user_id, intent=intent, duration_ms=duration)
logger.warning("LLM 调用超时，准备重试", attempt=attempt, max_retries=max_retries)
logger.error("工具调用失败", tool=tool_name, error=str(exc))
logger.critical("数据库连接失败", error=str(exc))
```

- 字段化输出，不要把变量拼进消息字符串。
- 必须脱敏：禁止记录密码、Token、完整身份证/银行卡、完整发票内容。

```python
# Bad
logger.info("用户信息", user=user)

# Good
logger.info("用户信息", user_id=user.id, name=user.name[:1] + "***")
```

## 13. SQLAlchemy 模型（2.0 风格）

使用 `Mapped[...]` + `mapped_column(...)`，`Base` 继承 `DeclarativeBase`。

```python
# app/admin_ai/db/models.py
from __future__ import annotations

import uuid
from datetime import datetime
from typing import Any, Optional

from sqlalchemy import Boolean, DateTime, String, JSON
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.admin_ai.db.database import Base


def generate_uuid() -> str:
    """生成 UUID 字符串。"""
    return str(uuid.uuid4())


class UserModel(Base):
    """用户模型。"""

    __tablename__ = "users"

    id: Mapped[str] = mapped_column(String(36), primary_key=True, default=generate_uuid)
    employee_id: Mapped[str] = mapped_column(String(50), unique=True, index=True, nullable=False)
    name: Mapped[str] = mapped_column(String(100), nullable=False)
    department: Mapped[Optional[str]] = mapped_column(String(100), nullable=True)
    is_active: Mapped[bool] = mapped_column(Boolean, default=True, nullable=False)
    # 注意：列名不能用 metadata，它是 SQLAlchemy 保留属性
    meta: Mapped[Optional[dict[str, Any]]] = mapped_column(JSON, nullable=True)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, nullable=False)
    updated_at: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.utcnow, onupdate=datetime.utcnow, nullable=False
    )

    conversations: Mapped[list["ConversationModel"]] = relationship(
        back_populates="user", cascade="all, delete-orphan"
    )

    def __repr__(self) -> str:
        return f"<UserModel(id={self.id}, employee_id={self.employee_id})>"
```

**模型规范：**

| 规范 | 说明 |
|------|------|
| 主键 | `String(36)` UUID，`default=generate_uuid` |
| 表名 | 小写下划线、复数 |
| 列名 | 小写下划线；**禁止** `metadata`（保留属性），用 `meta` |
| 可空性 | 显式写 `nullable=` |
| 时间字段 | `created_at` / `updated_at` 必须有 `default`，`updated_at` 加 `onupdate` |
| 关系 | 显式声明 `relationship`；同一目标两个外键时必须写 `foreign_keys=` |
| 索引 | 高频查询字段加 `index=True` |
| 迁移 | 表结构由 Alembic 管理，生产环境禁止 `Base.metadata.create_all` |
| `__repr__` | 每个模型都要有 |

## 14. FastAPI 路由与统一响应

### 14.1 统一响应信封

成功与失败统一为：

```json
{ "code": 0, "message": "success", "data": { } }
{ "code": 40001, "message": "参数错误", "details": { } }
```

```python
# app/admin_ai/api/response.py
from typing import Any, Generic, Optional, TypeVar

from pydantic import BaseModel

T = TypeVar("T")


class ApiResponse(BaseModel, Generic[T]):
    """统一响应信封。"""

    code: int = 0
    message: str = "success"
    data: Optional[T] = None


class ErrorResponse(BaseModel):
    """统一错误信封。"""

    code: int
    message: str
    details: Optional[dict[str, Any]] = None
```

- 业务异常继承 `AppError` 并携带 `code`，由全局 `@app.exception_handler` 转成 `ErrorResponse`。
- 路由层禁止直接抛 `HTTPException` 暴露内部细节；未预期异常统一转 `50001`。
- HTTP 状态码仍需语义化（400/401/403/404/429/500/502/503）。

### 14.2 路由写法

```python
# app/admin_ai/api/chat.py
from fastapi import APIRouter, Depends

from app.admin_ai.api.deps_context import APIContext, get_api_context
from app.admin_ai.api.response import ApiResponse
from app.admin_ai.api.schemas import ChatRequest, ChatResponse

router = APIRouter(prefix="/chat", tags=["对话"])


@router.post("/send", response_model=ApiResponse[ChatResponse])
async def send_message(
    payload: ChatRequest,
    context: APIContext = Depends(get_api_context),
) -> ApiResponse[ChatResponse]:
    """发送消息，创建或继续会话。"""
    result = await context.chat_service.send_message(
        user_id=context.user_id,
        message=payload.message,
        conversation_id=payload.conversation_id,
    )
    return ApiResponse(data=result)
```

- 依赖注入统一通过 `APIContext`（`deps_context.py`），路由不自己 new 服务。
- 请求体一律用 Pydantic 模型，不要用裸 `dict`。
- 路径参数用 `{task_id}` 形式，动词型操作用 POST。
- 认证依赖：`get_current_user`（普通用户）、`get_admin_user`（管理员）。

## 15. Pydantic Schema

```python
from datetime import datetime
from typing import Optional

from pydantic import BaseModel, ConfigDict, Field


class BaseSchema(BaseModel):
    """所有 Schema 的基类。"""

    model_config = ConfigDict(from_attributes=True, populate_by_name=True)


class UserCreateSchema(BaseSchema):
    """创建用户请求。"""

    employee_id: str = Field(..., min_length=1, max_length=50, description="工号")
    name: str = Field(..., min_length=1, max_length=100, description="姓名")
    email: Optional[str] = Field(None, max_length=200, description="邮箱")
```

| 规范 | 说明 |
|------|------|
| 命名 | 请求 `XxxCreateSchema` / `XxxUpdateSchema`，响应 `XxxResponse` |
| 继承 | 统一继承 `BaseSchema` |
| 配置 | 使用 `model_config`（Pydantic v2），**不要**用 `class Config` |
| 校验 | 用 `Field(...)` 声明约束 |
| 字段 | 所有字段必须有 `description` |

## 16. 测试风格

测试目录 `tests/admin_ai/` 与主包同构：

```text
tests/
├── conftest.py                 # 共享 fixture 与 marker 注册
└── admin_ai/
    ├── test_api/               # 接口测试
    ├── test_core/              # 单元测试
    └── test_services/          # 集成测试
```

```python
import pytest

from app.admin_ai.core.agent.intent import IntentRecognizer


class TestIntentRecognizer:
    """意图识别测试。"""

    @pytest.fixture
    def recognizer(self, mock_llm) -> IntentRecognizer:
        """构造带 mock LLM 的识别器。"""
        return IntentRecognizer(llm_client=mock_llm)

    async def test_recognize_leave_request(self, recognizer) -> None:
        """应识别出请假意图。"""
        # Arrange / Act
        result = await recognizer.recognize("我想请两天年假")

        # Assert
        assert result["intent"] == "leave_request"
        assert result["confidence"] >= 0.8
```

- 断言用原生 `assert`，不用 `self.assertEqual`。
- 异步测试统一 `@pytest.mark.asyncio`（或工程开启 `asyncio_mode = "auto"`）。
- 外部依赖用 `unittest.mock` 或 `respx`（httpx）打桩，测试不依赖真实网络/LLM。
- 共享 fixture 放 `conftest.py`；昂贵资源用 `scope="session"`。
- 自定义 marker 必须在 `conftest.py` 的 `pytest_configure` 注册（配合 `--strict-markers`）。

## 17. 工具链

```bash
# 格式化与静态检查（Ruff 同时负责 isort/black/flake8 的活）
ruff format app/ tests/

# 类型检查
mypy app/

# 测试
pytest tests/admin_ai -q

# 一键
ruff format app/ tests/ && ruff check app/ tests/ && mypy app/ && pytest -q
```

| 工具 | 职责 | 配置位置 |
|------|------|----------|
| Ruff | 格式化 + Lint（含导入排序） | `pyproject.toml` `[tool.ruff]` |
| mypy | 静态类型检查 | `pyproject.toml` `[tool.mypy]` |
| pytest | 测试 | `pyproject.toml` `[tool.pytest.ini_options]` |
| pre-commit | 提交前自动检查 | `.pre-commit-config.yaml` |

- **不再使用** Black / isort / flake8：它们的能力已由 Ruff 覆盖，重复配置只会产生冲突。
- 行宽 100。

## 18. 禁止事项

| 禁止 | 原因 |
|------|------|
| 裸 `except:` 或空 `except` 块 | 掩盖错误，必须捕获具体异常 |
| `print()` 输出日志 | 使用 structlog/logging |
| 在 `async def` 中同步阻塞 I/O | 阻塞事件循环 |
| 列名 `metadata` | SQLAlchemy 保留属性，直接报错 |
| 在代码中硬编码密钥 | 用环境变量 / `.env` |
| 通配符导入 | 命名污染 |
| 公共函数缺少类型注解 | 无法静态检查 |
| 生产环境 `Base.metadata.create_all` | 与 Alembic 冲突 |
| 记录未脱敏的敏感信息 | 合规风险 |
| 把 JWT 放在 WebSocket URL 里 | 会进入网关访问日志 |
