# 开发入门

更新：2026-10-06。当前 Windows 工作目录为 `D:\projects\admin-ai-agent`。

## 1. 先确认仓库

```powershell
Set-Location D:\projects\admin-ai-agent
git status --short --branch
git remote -v
```

`origin` 指向 `https://github.com/pretextQ/admin-agent.git`；`gitee` 保留原仓库地址。后续默认提交、推送到 GitHub。历史作者已经统一为项目所有者的 GitHub 身份，旧文档中的提交号不可直接作为当前基线。

开始新任务前先检查未提交修改，再更新本地分支。不要覆盖其他任务的改动。

## 2. 准备依赖

需要 Python 3.11+（建议先用 3.12）、uv、Node.js 20+、pnpm，以及可连接的 PostgreSQL 15+ 和 Redis。Node.js 的实际最低版本还需满足前端锁定的 Vite 依赖要求。

```powershell
uv venv --python 3.12
uv pip install --python .venv\Scripts\python.exe -r requirements-dev.txt
Copy-Item .env.example .env
```

已有 `.env` 时保留原文件，不重复覆盖。修改这些配置：

| 配置 | 本地开发要求 |
|---|---|
| `ENVIRONMENT` | 添加 `ENVIRONMENT=development` |
| `DATABASE_URL` | 指向你实际建立的 `admin_ai` 数据库，使用自己的本地账号与密码 |
| `REDIS_URL` | 指向可用的 Redis 实例 |
| `OPENAI_API_KEY` | 使用规则回退时设为空，删除示例 Key；需要模型时填写本地真实 Key |
| `OPENAI_BASE_URL` / `LLM_MODEL` | 按所选服务配置，两者必须匹配 |
| `DEBUG` | 本地需要 Swagger 时设 `true`；生产必须 `false` |
| `OA_SERVICE_URL` / `FINANCE_SERVICE_URL` / `MATERIAL_SERVICE_URL` | 开发桩分别为 8001、8002、8003 |
| `FEISHU_*` | 本地 dev-login 可不使用；联调 OAuth 时填写真实应用配置 |

`.env` 不提交。依赖定义在 `pyproject.toml`，当前后端 requirements 是版本范围清单，没有 `uv.lock`，不能将其当成完全锁定的环境。

旧的 `scripts/setup_dev_env.sh` 可在 Git Bash 中使用，但带有 `D:/NF/Tools`、`D:/NF/Redis` 等旧环境默认值，会安装、启动服务并初始化数据。当前机器尚未验证该脚本；使用前检查并配置 `TOOLS_DIR` / `REDIS_DIR`，不要直接假定旧路径可用。普通开发优先采用上面的手动步骤。

## 3. 建库与初始化

先在 PostgreSQL 中创建数据库 `admin_ai`，确认连接信息与 `.env` 一致，然后在项目根运行：

```powershell
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe scripts/seed_admin.py
.\.venv\Scripts\python.exe scripts/seed_org_demo.py
```

当前有 001、002、003 三份迁移。种子数据用于开发演示，包含管理员 `admin001`、员工 `emp999` 与技术部主管关系。真实组织数据后续通过 `scripts/sync_org.py` 接入，不能把演示账号用于生产。

## 4. 分终端启动

每个 PowerShell 终端先进入项目目录。

终端一：启动 OA、财务、物资开发桩。

```powershell
.\.venv\Scripts\python.exe scripts/dev_stubs.py
```

终端二：启动后端。

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.admin_ai.main:app --reload --host 127.0.0.1 --port 8000
```

终端三：启动前端。

```powershell
Set-Location D:\projects\admin-ai-agent\frontend
pnpm install --frozen-lockfile
pnpm dev
```

前端：`http://localhost:3000`；健康检查：`http://127.0.0.1:8000/api/health`；Swagger：`http://127.0.0.1:8000/docs`，仅 `DEBUG=true` 时开启。

本地登录检查（只在 development 环境可用）：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/auth/dev-login?employee_id=admin001'
```

健康检查只返回静态存活信息，不证明数据库、Redis、模型或下游系统就绪。

## 5. 验证后开始任务

按 [测试计划](测试计划.md) 跑所需检查，然后从 [开发计划](../planning/开发计划.md) 选择一个能独立验收的任务。优先统一假期余额、收紧 OAuth 校验和完善业务参数校验。

Linux/macOS 将 `.venv\Scripts\python.exe` 换成 `.venv/bin/python`，其他命令按本机 shell 调整；PostgreSQL、Redis 的安装和启动方式由本机环境决定。
