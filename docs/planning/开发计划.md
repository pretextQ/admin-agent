# 开发计划

更新：2026-10-06。本文件是后续开发任务与验收标准的唯一清单；实现与验证现状见 [当前状态](../guides/当前状态.md)。下面均为未完成或待核验项，没有因本轮文档整理而视为已修复。

## 1. 推荐推进顺序

1. 按 [开发入门](../guides/开发入门.md) 建立本机环境，验证迁移、单元测试和开发桩冒烟。
2. 做正确性与安全修复：假期余额、OAuth state、金额/数量、审计脱敏、重复确认。
3. 明确并实现审批与下游单据的完整生命周期，先跑通一个真实业务场景。
4. 接通制度问答的嵌入模型和降级回复，再完善管理后台与其他场景。
5. 完成部署、监控、故障测试与小范围试点后，再扩大使用范围。

不要同时展开全部 11 个场景。每个任务独立提交、附相关验证结果；纯格式与业务修改分开。

## 2. P0：先保证业务正确和授权可靠

| ID | 任务与代码入口 | 验收标准 |
|---|---|---|
| P0-01 | 统一查询与校验的假期余额来源：`core/rules/engine.py`、`core/status_query.py`、HR 适配 | 同一员工两条路径余额一致；超额申请拒绝；HR 超时有明确行为；不使用默认 10 天放行 |
| P0-02 | OAuth state 故障时拒绝继续：`api/auth.py` | state 缺失、失效、复用、Redis 不可用均不能换取登录态；测试涵盖 production 与 development |
| P0-03 | 业务参数强校验：规则引擎与工具适配器 | 负数/零/非数字金额和数量、非法日期、未知 action 明确拒绝；未授权字段不转发下游 |
| P0-04 | 审计与异常日志脱敏：`middleware/audit.py`、编排器异常分支 | 手机、证件、银行卡、令牌等不以明文进入审计或日志；能保留动作、结果、操作者等必要证据 |
| P0-05 | 重复提交与并发确认防护：`api/chat.py`、状态存储、工具接口 | 相同待确认操作并发调用只执行一次；失败后恢复/重试规则明确；下游结果与本地任务一致 |
| P0-06 | 明确草稿、审批、执行的边界并闭环：`api/chat.py`、`api/task.py`、工具层 | 审批前只产生允许的草稿/申请；拒绝不产生最终效果；通过后只执行一次；取消与失败可追溯 |
| P0-07 | 核验审批步序、停用账号和授权变化 | 后一步不能越过前一步审批；停用员工不能继续办理；角色变化的生效时机明确且有回归用例 |
| P0-08 | 核验知识删除一致性及失效文档引用 | 向量库删除失败可重试，问答不引用已失效文档；空检索不会一直回复“正在查询” |

## 3. P1：完成可用的产品闭环

| ID | 任务 | 验收标准 |
|---|---|---|
| P1-01 | 确定并接入 RAG 嵌入模型，建立索引重建流程 | 真实中文制度可检索；写入、查询使用一致模型；切换模型可重建索引；pending_index 明确提示并可重试；无命中/超时明确回复 |
| P1-02 | 完善制度回答、引用和知识运营 | 回答保留可追溯来源；指定内容负责人、复核和有效期；有中文样例集评估相关性与忠实度 |
| P1-03 | 对接真实 HR/OA/财务/物资接口与组织数据 | 契约、鉴权、超时、幂等、错误码有约定；主管与 HR/法务角色完整；至少一个场景真实联调通过 |
| P1-04 | 审批回调与必要的补偿查询/轮询 | 回调验签/鉴权；重复与乱序回调安全；状态收敛；不把本地 completed 当成下游执行成功 |
| P1-05 | warnings、超标准特批、物资单价与紧急通道 | 超标与缺材料提示能显示/阻止或升级审批；规则与场景设计一致 |
| P1-06 | 转人工通知、人工指派、外部系统故障降级 | 自动与手动转人工均可通知负责人；业务失败不只留下日志；恢复后的处理与一致性可测试 |
| P1-07 | 明确车辆预定路由并修复工具目录 | 意图能准确映射车辆或明确不支持；工具列表无重复 calendar 命名；无不可达注册项冒充能力 |
| P1-08 | 管理后台首期：审批规则、组织、审计 | 确认交付范围后按 [后台方案](../frontend/管理后台前端技术方案设计.md) 实现；鉴权、错误与审计可验收；用户清单是否纳入首期单独决定 |
| P1-09 | 员工前端完善与测试 | 审批状态与后端一致；分页正常；确认卡片动作受支持；加签、401、空状态有可验证交互 |
| P1-10 | 文件服务与 PDF/Word 解析（如纳入首期） | `/files` 实现与 API 文档一致；类型/大小/归属检查、私有存储与扫描机制有验证；否则明确使用文本知识上传 |

## 4. P2：工程整理与上线准备

| ID | 任务 | 验收标准 |
|---|---|---|
| P2-01 | 死代码、重复服务、无效配置与依赖清理 | 按实际调用逐项核对后移除或接通；不删除有调用的 notification_service；测试通过；依赖可复现 |
| P2-02 | Ruff / mypy、依赖锁定、pre-commit 与 CI | 在选定版本下记录真实检查结果；纯格式单独提交；仓库提供实际配置，不只放文档示例 |
| P2-03 | 补规则、工具、OAuth 与并发异常测试 | 正常、越权、超时、部分成功、重试路径覆盖；覆盖率实测达到约定目标，不能仅引用目标数字 |
| P2-04 | Docker / Compose / nginx 与环境配置 | 仓库有可运行文件；迁移、持久卷、健康检查、密钥注入经过干净环境验证 |
| P2-05 | 指标、成本、限流与容量验证 | LLM 次数/Token/耗时有真实埋点；限流产生 429；告警能触发；按需求分级指标压测 |
| P2-06 | 数据备份、保留期与清理 | PostgreSQL 可恢复；向量索引可重建；清理任务遵循批准的保留期；恢复演练有记录 |
| P2-07 | 多实例、会话与成本策略 | 状态与脱敏映射一致；过期会话安全清理；跨设备、长会话、Token 上限及供应商切换明确 |
| P2-08 | 上线配置、组织同步定时与试点验收 | 使用真实组织和规则；密钥、访问范围、人员职责明确；通过 [上线检查](../guides/部署与运维.md#9-上线检查) 后进行小范围试点 |

## 5. 待项目所有者确定的范围

| 事项 | 在开始相关开发前明确 |
|---|---|
| 嵌入模型 | 本地模型还是外部服务、中文效果、硬件/费用与索引迁移 |
| 首期范围 | 优先验证的真实业务场景；管理后台、文件服务、车辆、WebSocket 是否首期交付 |
| 业务规则 | HR 余额来源、下游草稿/执行语义、审批生效边界与超标处理 |
| 模型与数据 | 供应商、超时/重试/成本预算、训练用途与留存/删除承诺、金额脱敏与敏感业务策略 |
| 运维与运营 | 内网/外网访问、内容负责人、行政/财务审核人、组织同步、基础设施预算与试点范围 |

确认接口现阶段使用 `/chat/confirm/{conversation_id}`。本轮将文档对齐实现，不要求改成 task_id；未来若要改变资源语义，应另立接口迁移任务。

## 6. 后置想法

跨用户对话查询（需姓名消歧与授权）、新人引导、更多行政场景、ROI/满意度、意图线上抽样、后台二期、组织缓存与旧 department 列收缩，纳入 [想法池](想法池.md)。这些都没有本期完成承诺。

WebSocket 可继续后置，但现有未鉴权回显端点在上线前必须关闭或补齐控制；不因前端暂时不用而直接暴露到生产。
