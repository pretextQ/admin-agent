## 1. 背景与问题

### 1.1 现状

系统有三条链路会把数据送往**外部 LLM**（当前为 DeepSeek）：

| 链路 | 代码位置 | 送出的数据 |
|------|----------|-----------|
| 意图识别 | `core/agent/intent.py` → `recognize(message)` | **用户原话** |
| 槽位抽取 | `core/agent/slot.py` → `extract(message, ...)` | **用户原话** + 已收集槽位 |
| 回复生成 | `core/agent/orchestrator.py` → `_compose_reply` | 业务槽位（含**金额**、姓名）+ 工具返回内容 |

而 `SECURITY.md` §3.2 的约束只覆盖到 L4：

> 「L4 数据不得进入日志、缓存明文、向量库与 LLM Prompt」

**L3 数据（员工姓名/工号/联系方式、假期余额、报销金额、发票影像、对话内容）没有同等约束**，
实际会原样离开公司边界。典型场景：

- 「我要请病假，附诊断证明」——健康信息（PIPL 敏感个人信息）
- 「帮张伟开在职证明」——他人姓名 + 人事意图
- 「报销 8000 元客户招待费」——金额 + 业务敏感信息

### 1.2 合规要求

| 要求 | 来源 | 本设计如何满足 |
|------|------|----------------|
| 告知同意 + 最小必要 | PIPL 第 6、13、17 条 | 送出字段白名单 + 逐类脱敏（§3、§4） |
| 委托处理需签订协议并监督 | PIPL 第 21 条 | 供应商数据处理协议三要素（§5） |
| 处理活动可自证 | PIPL 第 55、56 条（PIA 要求） | 调用审计记录脱敏类别（§6） |
| 核心数据不出域 | SECURITY §3.4 | 敏感业务本地化处理（§7） |

### 1.3 目标

1. **默认安全**：新增 LLM 调用点无需逐个考虑脱敏——脱敏发生在统一出入口；
2. **能力不受损**：脱敏后意图识别与回复质量不明显下降（占位符对 LLM 仍是有效语义信号）；
3. **可自证**：任意时刻能回答「过去某次调用送出了哪几类数据、送给了谁、是否脱敏」。

## 2. 设计原则

1. **最小必要**：只送完成任务所需的最小字段；能本地判定（规则/缓存）就不调 LLM。
2. **先脱敏后出网**：脱敏发生在**调用 LLM 之前的最后一个环节**（统一出入口），不依赖调用方自觉。
3. **可逆但不落真值映射**：占位符 ↔ 真值映射仅存在于**会话期内存/Redis**，不入库、不进日志。
4. **失败即拒绝**：脱敏组件异常时**不得降级为直发原文**——应回退到规则路径（不调 LLM）。
5. **敏感业务不上云**：L4 与部分 L3 场景（见 §7）走本地规则/模板，不调用外部 LLM。

## 3. 数据送出白名单

按「字段类别 × 是否可送外部 LLM」定义，作为实现与评审的对照表：

| 数据类别 | 分级 | 是否可送 LLM | 处理方式 |
|----------|------|--------------|----------|
| 制度/流程类问题文本 | L1 | ✅ 可原样送 | 无需处理 |
| 业务类型、日期、类型枚举（如「年假」「2026-09-25」「酒店」） | L2/L3 | ✅ 可送 | 无需处理（非身份信息） |
| 金额 | L3 | ⚠️ 可送（需 DPA 约定） | 可保留数值；若企业要求更严，替换为占位符并在回复中回填 |
| 员工姓名 | L3 | ⚠️ 脱敏后送 | 替换为 `[员工A]` 类占位符（§4.2） |
| 工号 / 员工 ID | L3 | ⚠️ 脱敏后送 | 替换为占位符；LLM 不需要真实工号 |
| 手机号、邮箱 | L3 | ❌ 不送 | 替换为占位符（LLM 无需真实值） |
| 身份证号、银行账号 | L4 | ❌ **绝不送** | 命中即拦截该次 LLM 调用（§7） |
| 薪资、合同金额与条款 | L4 | ❌ **绝不送** | 命中即拦截该次 LLM 调用 |
| 附件原文/发票影像 | L3/L4 | ❌ 不送 | 仅送解析后的结构化字段（如金额、类型），且遵守本表 |
| 诊断证明、病假原因等健康信息 | 敏感个人信息 | ❌ 不送 | 仅送「病假」类型枚举，不送原因描述 |
| 工具返回的原始报文 | — | ⚠️ 按字段判定 | 先做字段级过滤（白名单字段），再套用本表 |

> 实现提示：`§4` 的脱敏器按**正则 + 类别白名单**工作；`§7` 的拦截器按**命中即拒绝**工作。
> 两者是不同机制，前者改写文本，后者中止调用。

## 4. 脱敏层设计

### 4.1 位置与调用链

脱敏层作为**外部 LLM 的唯一出入口**，位于 `core/llm.py` 与各调用点之间：

```
IntentRecognizer / SlotExtractor / Orchestrator._compose_reply
        │  （调用方不再直接持有 AsyncOpenAI）
        ▼
  LLMGateway.chat(messages, purpose)          ← 新增：统一出入口
        ├─ 1. 白名单校验（§3）
        ├─ 2. L4 命中检测 → 命中则拒绝并抛 RedactionBlocked（§7）
        ├─ 3. 脱敏改写（§4.2）+ 登记占位符映射（§4.3）
        ├─ 4. 调用供应商 API
        ├─ 5. 回填占位符（§4.4）
        └─ 6. 写调用审计（§6，仅记录类别，不含值）
```

**改造要点**：`core/llm.py` 的 `build_llm_client()` 从"返回 AsyncOpenAI 客户端"改为
"返回 `LLMGateway` 实例"，调用方签名不变（仍是 `gateway.chat.completions.create(...)` 或
统一为 `gateway.chat(messages, purpose)`），以最小化改动面。

### 4.2 脱敏规则

按类别定义，规则可配置（§4.5），默认集：

| 类别 | 识别方式（示例正则） | 替换为 |
|------|---------------------|--------|
| 手机号 | `1[3-9]\d{9}` | `[手机N]` |
| 邮箱 | `[\w.+-]+@[\w-]+\.[\w.]+` | `[邮箱N]` |
| 工号 | 可配置前缀（如 `EMP\d{4,}`） | `[工号N]` |
| 姓名 | 见下 | `[员工N]` |
| 金额 | `(\d+(?:\.\d+)?)\s*元` | 保留（默认）；配置 `REDACT_AMOUNT=true` 时替换为 `[金额N]` |

> **身份证与银行卡不在此表**：它们属 L4，按 §3 白名单与 §7 拦截处理——
> **命中即中止调用**，不做"脱敏后送出"（原文一旦送出即不可撤回，脱敏不是等价替换）。
> 实现中二者列在 `DEFAULT_BLOCKED_PATTERNS`，见 `core/llm_redaction.py`。

**姓名的处理策略**（准确率与成本的权衡）：

- **优先**：从上下文中已知的姓名集合做精确匹配替换——
  申请人的 `name`、审批人姓名、以及会话中已出现过的姓名（可从 `users` 表按会话用户所在部门限定范围）。
  这比通用 NER 准确得多，且零额外成本。
- **可选增强**：配置启用轻量 NER（如本地 `jieba` + 姓氏表），用于捕获未知人名；
  误判代价是回复中少一个真实姓名（可回填），可接受。
- **不追求 100%**：漏脱敏的残留姓名仍属内部信息外发风险，但相较"全部原样送出"风险已大幅下降；
  真正的兜底是 §5 的 DPA 与 §6 的可自证。

### 4.3 占位符与会话内映射

**关键约束：同一会话内，同一实体必须映射到同一占位符**，否则 LLM 会把「张三」和「[员工1]」「[员工2]」
当成不同的人，导致多轮对话语义错乱。

```
映射表（会话级，存放在会话状态存储中，与 ConversationState 同生命周期）
{
  "会话ID": {
    "张三": "[员工1]",
    "[员工1]": "张三",      # 反向用于回填
    "13812345678": "[手机1]",
    ...
  }
}
```

- 存储位置：复用 `ConversationStateStore` 的存储（Redis 或内存），**不落 PostgreSQL**，
  TTL 与会话状态一致（当前 86400 秒）；
- 占位符编号在会话内单调递增、不复用（避免"员工1"指向不同人）；
- 会话结束后映射自然过期，不保留跨会话的真值关联。

### 4.4 回填

LLM 生成的回复中若含占位符，必须回填为用户可读的真实值：

```python
# 回填发生在 LLMGateway 内部，调用方拿到的是已回填文本
reply = gateway.chat(messages, purpose="reply_generation")
# 内部：response → replace("[员工1]", "张三") → 返回
```

- 回填**只作用于回复文本**，不写回状态、不进日志；
- 若 LLM 返回了未登记的占位符（幻觉），保留原样（不猜测），并记一条 warn 日志（不含上下文值）。

### 4.5 配置项

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `LLM_REDACTION_ENABLED` | `true` | 关闭仅允许在 development；production 启动时**强制为 true**（fail-fast） |
| `LLM_REDACTION_RULES` | 内置默认集 | 可覆盖/扩展的规则清单（类别、正则、替换模板） |
| `REDACT_AMOUNT` | `false` | 是否连金额一并占位化（合规要求更严时开启） |
| `LLM_BLOCKED_PATTERNS` | 身份证/银行卡正则 | 命中即拒绝该次调用的模式（§7） |
| `LLM_AUDIT_ENABLED` | `true` | 是否记录调用审计（§6） |

新增配置项须同步进 `config.py` 的 `Settings`、`.env.example` 与 `部署与运维.md` §2.3 的配置清单
（三者齐步，见工程硬约定）。

## 5. 供应商合规要求

选用外部 LLM 供应商前，须确认并留存以下三项书面约定（DPA 核心条款）：

| # | 条款 | 要求 | 验收方式 |
|---|------|------|----------|
| 1 | **不用于训练** | 调用数据不得用于模型训练或改进 | 合同/服务条款截图归档 |
| 2 | **留存期限** | 明确留存天数（建议 ≤30 天），到期自动删除 | 供应商文档 + 书面确认 |
| 3 | **可删除** | 支持按请求删除（或提供删除窗口） | 书面确认删除流程 |

补充要求：

- **数据存储地**：优先境内节点；若涉及境外，须单独做数据出境评估（PIPL 第 38、39 条），
  并在 `SECURITY.md` §3.4「跨境」条目下登记；
- **可审计**：供应商需能提供调用日志用于对账（本系统侧审计见 §6，两侧可交叉核对）；
- **变更通知**：供应商条款或模型下线需提前通知（建议 ≥30 天），以便切换（见 §8.2）。

> 现状：`.env` 已使用 DeepSeek；**上线前须补齐上述三项书面确认并归档**，
> 否则 B-1 视为未关闭。

## 6. 审计与可自证

每次 LLM 调用记录一条审计（写入现有 `audit_logs` 或独立的 `llm_call_logs` 表）：

| 字段 | 内容 | 是否含敏感值 |
|------|------|--------------|
| `purpose` | 调用用途（intent / slot / reply / policy_answer） | 否 |
| `model` | 模型名 | 否 |
| `redacted_categories` | 本次命中的脱敏类别，如 `["person","phone"]` | 否（仅类别） |
| `blocked` | 是否被拦截（L4 命中） | 否 |
| `prompt_tokens` / `completion_tokens` | token 用量（供成本统计） | 否 |
| `latency_ms` | 耗时 | 否 |
| `trace_id` | 关联请求 trace | 否 |

**明确不记录**：提示词原文、回复原文、任何真值。
（原文已由 `messages` 表按权限保存，无需在 LLM 审计中重复留存。）

这使得"哪些数据发给了谁"可自证：给定时间范围，可导出**类别级**的调用清单交付合规审查。

## 7. 拦截与降级（敏感场景不出网）

### 7.1 命中即拦截

当待送内容命中 `LLM_BLOCKED_PATTERNS`（身份证、银行账号、合同条款等 L4 特征）时：

1. **中止**该次 LLM 调用，抛 `RedactionBlockedError`；
2. 调用方按业务语义降级：
   - 意图识别 → 规则回退（`_fallback_recognize`，已存在）
   - 槽位抽取 → 规则回退（`_fallback_extract`，已存在）
   - 回复生成 → 模板回退（`_compose_reply` 的 fallback，已存在）
3. 记审计（`blocked=true`）并告警（若同一用户高频触发，可能是在试探或误用）。

### 7.2 敏感业务策略（建议）

以下业务建议**默认不走外部 LLM 生成**，只用规则 + 模板：

| 业务 | 原因 | 处理 |
|------|------|------|
| 证明开具（在职/收入/离职证明） | 常含薪资等 L4 信息 | 槽位抽取走规则；回复用模板 |
| 用印/合同 | 合同条款属商业机密 | 同上 |
| 涉及身份证/银行账号的任何场景 | L4 明确禁出域 | 同上 |

实现方式：在业务类型维度配置 `LLM_EXCLUDED_BUSINESS_TYPES`，命中时 `LLMGateway` 直接拒绝并触发模板路径。

## 8. 实现与落地

### 8.1 改动清单

| 文件 | 改动 | 说明 |
|------|------|------|
| `core/llm.py` | 新增 `LLMGateway`，`build_llm_client` 返回它 | 统一出入口 |
| `core/llm_redaction.py` | 新增：脱敏器 + 占位符映射 + 回填 | 独立模块，便于单测 |
| `core/agent/intent.py` / `slot.py` / `orchestrator.py` | 改为经 `LLMGateway` 调用 | 签名尽量不变，减少 diff |
| `core/agent/state_store.py` | `ConversationState` 增 `placeholder_map`（可选字段） | 与会话同生命周期 |
| `db/models.py` | 新增 `LLMCallLogModel`（或复用 audit_logs） | §6 审计 |
| `config.py` / `.env.example` | 新增 §4.5 配置项 | production fail-fast 校验 `LLM_REDACTION_ENABLED=true` |
| `SECURITY.md` | 新增「LLM 数据出域」章节，引用本设计 | 关闭 B-1 的文档侧 |

### 8.2 降级矩阵（LLM 不可用/被拦截）

| 场景 | 用户可见行为 | 实现 |
|------|--------------|------|
| LLM 超时/报错 | 正常办理，回复为模板话术 | 现有 `_compose_reply` fallback |
| 命中 L4 拦截 | 正常办理，走规则 + 模板 | 现有规则回退路径 |
| 脱敏组件异常 | **拒绝调用**，走规则路径 | 原则 4：失败即拒绝 |
| 供应商停服/涨价 | 切换到备用供应商 | 见 §8.3 |

### 8.3 供应商可替换（配合评审 I-2）

`LLMGateway` 内部持有供应商配置，支持主/备双配置：

```
LLM_PRIMARY:   { base_url, model, api_key_ref }
LLM_FALLBACK:  { base_url, model, api_key_ref }   # 可选
```

切换耗时目标 ≤1 小时（改配置 + 重启，无需改代码）。切换前须对新供应商重复 §5 的三项确认。

|---|------|------|
