## 五、工程硬约定（违反会翻车，全部有前科）

详见 `docs/guides/开发规范.md` §3.1，速记：

1. **时间**一律 `from app.admin_ai.db.models import utc_now`，禁止 `datetime.utcnow()` / `now(timezone.utc)` 混用（jwt 签发除外，那里必须 aware）。
2. **模型枚举列**必须 `SAEnum(X, values_callable=lambda x: [e.value for e in x])`——PG 原生枚举是小写 value，SAEnum 默认绑大写 name，不写这个任务表写入直接报错。
3. **Redis** 所有 `from_url` 显式 `protocol=2`；连接走 `db/redis.py` 单例。
4. **写接口端点内显式 `await db.commit()`**——依赖 teardown 的提交在响应之后，会造成读写竞态。
5. Chroma 等同步客户端必须 `asyncio.to_thread` + 超时（`RAG_TIMEOUT_SECONDS=30`）。
6. 新中间件必须注册进 `main.py`（TraceId 最外层）；`/admin/*` 必须挂 `get_admin_user`；会话状态必须校验属主。
7. 分页统计用 `db.scalar(select(func.count())...)` 全量集合，不要对当前页做 Python 计数。

## 六、环境踩坑速查（本机实测）

| 症状 | 原因与解法 |
|------|-----------|
| PG 起不来："administrative permissions is not permitted" | PG 拒绝管理员账户。当前用普通用户 + 绿色二进制方式，勿用管理员身份跑 `postgres.exe` |
| `initdb -D /d/NF/...` 报成功但目录找不到 | MSYS 把 `/d/...` 当盘符相对路径，实际建到 `D:\d\NF\...`。先用 `export MSYS_NO_PATHCONV=1`，路径写 `D:/NF/...` |
| Redis 起不来："listen: 提供了一个无效的参数" | 少了 `--bind 127.0.0.1` |
| 运行时报 `unknown command 'HELLO', with args beginning with: '3'` | redis-py 8 RESP3 vs Redis 5，需 `protocol=2`（已全改，新增连接点要记得加） |
| 任务列表计数为 0 但明细有数据 | teardown 提交竞态，写接口要显式 commit |
| Windows 枚举值无效 `对于枚举taskstatus的输入值无效: "PENDING"` | 见硬约定 #2 |
| `pnpm build` 报 `'node' 不是内部或外部命令` | Windows 系统 PATH 没有 nodejs（仅 Git Bash 注入）。`export PATH="/c/Program Files/nodejs:$PATH"` |
| `psql -f /d/NF/...` 报 `No such file or directory` | psql 是 Windows 程序，MSYS 路径被当盘符相对路径。用 `cygpath -w` 转成 `D:\NF\...`（`scripts/db_backup.sh` 已内置） |
| 导入含中文的 SQL 报 `invalid byte sequence for encoding "UTF8"` | Windows 下 psql 客户端编码不是 UTF8。`export PGCLIENTENCODING=UTF8`（`scripts/db_backup.sh` 已内置） |
| Git Bash 里 Windows 命令报路径错误 | `export MSYS_NO_PATHCONV=1` |
| 系统只有 Python 3.8，本项目要求 ≥3.11 | 用 `D:\NF\Tools\uv.exe` 隔离装 3.12，**不要**升级/污染系统 Python 3.8（用户其他工作依赖它） |
