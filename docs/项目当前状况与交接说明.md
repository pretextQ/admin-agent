### 本机环境特殊性（Windows + Git Bash）

- **PostgreSQL 服务名 `AdminAIPG`**，以 `NT AUTHORITY\NETWORK SERVICE` 运行（PG 拒绝管理员账户启动），数据目录 `Z:\zcode\.installers\pgdata`，二进制 `Z:\zcode\.installers\pg\bin`。连接串 `postgresql://postgres@localhost:5432/admin_ai`（trust 认证）。
- **Redis 是 tporadowski 5.0.14 Windows 版**：必须 `--bind 127.0.0.1` 显式绑定；应用侧 redis-py 8 已全部显式 `protocol=2`（RESP3 握手会被它拒绝）。**它不是 Windows 服务**，机器重启后要手动起。
- **国际网络受限**：下载一律走国内镜像——pip 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`，npm/pnpm 用 `https://registry.npmmirror.com`，GitHub 走 `https://ghfast.top/` 前缀。winget 已损坏勿用。
- **Git Bash 会把 `/xxx` 参数当路径转换**：调 Windows 原生命令（net/schtasks/icacls 等）前 `export MSYS_NO_PATHCONV=1`。
- 当前 `.env`：`DEBUG=true`（SQL echo 很吵，属正常）、`OPENAI_API_KEY` 为空（LLM 走规则回退）。

## 五、工程硬约定（违反会翻车，全部有前科）

详见 `docs/guides/开发规范.md` §3.1，速记：

1. **时间**一律 `from app.admin_ai.db.models import utc_now`，禁止 `datetime.utcnow()` / `now(timezone.utc)` 混用（jwt 签发除外，那里必须 aware）。
2. **模型枚举列**必须 `SAEnum(X, values_callable=lambda x: [e.value for e in x])`——PG 原生枚举是小写 value，SAEnum 默认绑大写 name，不写这个任务表写入直接报错。
3. **Redis** 所有 `from_url` 显式 `protocol=2`；连接走 `db/redis.py` 单例。
4. **写接口端点内显式 `await db.commit()`**——依赖 teardown 的提交在响应之后，会造成读写竞态。
5. Chroma 等同步客户端必须 `asyncio.to_thread` + 超时（`RAG_TIMEOUT_SECONDS=30`）。
6. 新中间件必须注册进 `main.py`（TraceId 最外层）；`/admin/*` 必须挂 `get_admin_user`；会话状态必须校验属主。
7. 分页统计用 `db.scalar(select(func.count())...)` 全量集合，不要对当前页做 Python 计数。

## 六、环境踩坑速查（本机实测）

| 症状 | 原因与解法 |
|------|-----------|
| PG 起不来："administrative permissions is not permitted" | PG 拒绝管理员账户。已用 NETWORK SERVICE 服务方式解决（AdminAIPG），勿再用当前用户直接 `postgres.exe` |
| Redis 起不来："listen: 提供了一个无效的参数" | 少了 `--bind 127.0.0.1` |
| 运行时报 `unknown command 'HELLO', with args beginning with: '3'` | redis-py 8 RESP3 vs Redis 5，需 `protocol=2`（已全改，新增连接点要记得加） |
| 任务列表计数为 0 但明细有数据 | teardown 提交竞态，写接口要显式 commit |
| Windows 枚举值无效 `对于枚举taskstatus的输入值无效: "PENDING"` | 见硬约定 #2 |
| Git Bash 里 Windows 命令报路径错误 | `export MSYS_NO_PATHCONV=1` |
| corepack/npm 下载 pnpm 超时、chroma 嵌入模型下载卡死 | 国际网络受限。pnpm 用 npmmirror；chroma 超时会自动降级（30s），不影响业务 |
| winget 报 0x8a15000f | 源损坏，放弃 winget，改官网/镜像直接下载 |

## 七、待办清单（按优先级）

### P0 — 影响核心体验（建议接手先做）

1. **配置 LLM Key**（当前规则回退：意图/槽位准确率受限，最终回复全是模板）。
   做法：`.env` 填 `OPENAI_API_KEY`（兼容 OpenAI 协议即可，配 `OPENAI_BASE_URL`），重启后端。代码已就绪（`core/llm.py`），无代码改动。
2. **RAG 嵌入模型落地**（当前检索会 30s 超时降级，制度问答实际没有真实向量结果）。
   方案 A：设置 `HF_ENDPOINT=https://hf-mirror.com` 让 sentence-transformers 走国内镜像下载模型；
   方案 B：`docker compose` 起 Chroma 服务端（8005），`build_retriever` 会自动探活优先走服务。
3. **`/chat/transfer` 转人工落地**：现在是假话术（`api/chat.py` 末尾）。最小可用：写 `conversations.status=transferred` + 通知（notification_service 目前只打日志）。

### P1 — 功能闭环

4. **status_query（查进度/余额）**：意图已识别（`orchestrator.py` 返回 `needs_status_query` 无人消费）。数据都在库里（tasks/approvals），实现"查我的请假进度/假期余额"即可闭环场景 03。
5. **WebSocket 接编排器 + JWT 鉴权**：`api/websocket.py` 是 echo 桩；前端也完全没用 WS（纯 HTTP）。鉴权方案见 SECURITY.md（禁止 URL 传 token，用 query 参数带一次性 ticket 或 subprotocol）。
6. **真实 OA 审批回调**：架构文档定义了 `POST /approvals/callback`（X-Callback-Token + 幂等）与 Celery 5 分钟轮询。当前审批闭环全在本地库内完成，对接真实 OA 时需要做状态同步。
7. **知识库向量化补 PDF/Word 解析**：现在只支持纯文本内容（`chunk_text`）。

### P2 — 工程收尾

8. **死代码清理**：`services/` 三层空壳（chat_service 无人调用）、`db/schemas.py`、`utils/exceptions.py`（两套异常体系）、`api/deps_context.py`、前端 `useAppStore`/`useAuth`/`isFeishuEnv`、`@tanstack/react-query`（装了没用）与飞书主题包。
9. **配置项清理**：`LLM_TEMPERATURE`（硬编码 0）、`RATE_LIMIT_DEFAULT`（限流未实现）、`SSO_ENABLED/SSO_URL`、Celery 配置——用起来或删掉。
10. **Docker 部署文件落地**：`docs/guides/部署与运维.md` §3 里有完整模板，复制调通即可。
11. **规则引擎配置化**：假期余额/报销标准硬编码在 `core/rules/engine.py`（`DEFAULT_LEAVE_BALANCE`/`EXPENSE_STANDARDS`），构造参数 `user_service/config_service` 收了没用。
12. **规则 warnings 无消费方**：超标准/病假条等 warning 生成后被丢弃，应拼进回复或写任务。
13. **前端细节**：任务列表无分页（写死 50）、ConfirmCard 忽略 `type`/`actions` 字段、401 用 alert、任务筛选 tab（pending/approving）与后端统计联动。
14. **测试补缺**：services 层零测试、WS 无测试、`test_health.py:38` 的 integration 用例 mock 不全会挂（默认已跳过）、覆盖率未达声明的 80%。
